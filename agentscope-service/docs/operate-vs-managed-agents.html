Operate (Dashboard) vs Managed Agents

AgentScope Service 控制台的双系统架构设计与使用场景

核心区别

Operate / Dashboard

运行中的进程

类比：Kubernetes 中的 Pod（运行实例）
数据源
dataplane 注册表（内存，运行时）
API
/api/v1/agents
创建方式
Java 代码通过 Aistio SDK 自注册
生命周期
进程在就在，进程挂了就消失
关注点
存活状态、副本数、健康度、心跳
Managed Agents

版本化的配置定义

类比：Kubernetes 中的 Deployment（声明式配置）
数据源
产品数据库 cp.agents 表（持久化）
API
/api/agents
创建方式
控制台 UI 或 POST /api/agents
生命周期
持久存在，不依赖任何进程
关注点
系统提示词、模型、工具、会话历史

详细对比

维度 Operate (Dashboard) Managed Agents
本质 一个运行中的进程实例 一份版本化的配置定义
API 前缀 /api/v1/agents /api/agents
存储 内存（dataplane registry） PostgreSQL（cp.agents 表）
创建者 Agent 进程自身（自注册） 用户（控制台或 API）
执行方式 自己的进程执行 共享 service-dataplane 懒加载
持久性 临时的（重启消失） 持久的（数据库存储）
版本管理 无 支持（agent_versions 表）
Session 对话 ❌ 不支持 ✅ 支持
Deployment 发布 ❌ 不支持 ✅ 支持
视角 SRE / 平台运维 构建者 / 最终用户

架构流程

Operate (Dashboard) — 自注册 & 监控

你的 Java 应用（Agent 进程） │ │ Aistio SDK 自注册 ▼ dataplane registry（内存注册表） │ │ 轮询 /agentscope/* 获取状态 ▼ Dashboard 展示： • 实例数 / 副本数 • 健康状态（healthy / unhealthy） • 心跳状态 • 合约级别（contractLevel） • 活跃 session 数

Managed Agents — 配置定义 & 对话执行

控制台 UI / API 创建 │ ▼ 产品数据库 cp.agents 表： • 名称、描述 • 系统提示词 • 模型配置 • 工具 / 技能 / MCP • 版本号 • 工作区 │ │ 用户创建 Session 时 ▼ service-dataplane 懒加载执行： resolveSession → HarnessAgent → 运行 Agent

使用场景

Operate (Dashboard) 适合

自带 Agent 框架

你有自己的 Agent 实现（如 agentscope-paw），通过 SDK 注册到平台

运维监控

查看 Agent 实例的运行状态、健康度、副本数

自定义运行时

你的 Agent 有特殊运行时需求，需要自己管理进程生命周期

BYO（Bring Your Own）

自带 Agent 接入平台的基础设施监控

Managed Agents 适合

控制台创建 Agent

在 UI 中配置 Agent 的提示词、模型、工具

Session 对话

通过 Session API 或控制台 Chat 面板直接对话

Deployment 发布

创建 webhook / cron / manual 触发器

版本管理

Agent 配置的版本控制和回滚

多用户共享

多个用户共享同一个 Agent 定义

业务系统集成

通过 Session API 程序化调用

一句话总结

🔍 Operate = "你的 Agent 进程在跑吗？"（运维视角 — 监控运行状态）
🛠️ Managed Agents = "你的 Agent 应该怎么工作？"（产品视角 — 定义对话能力）
两套系统不互通

通过 Java SDK 注册的 Agent 只出现在 Dashboard 中，不能直接用 Session API 对话或 Deployment 发布。如果需要这些功能，需要在 Managed Agents 中创建对应的 Agent 定义。
