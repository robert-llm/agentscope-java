前置准备

前提条件

你的 Agent 已通过代码注册到 AgentScope Service 平台，且服务已启动（默认端口 8080）。

基础对话（非流式）Postman 友好

1 登录获取 JWT Token

POST http://localhost:8080/api/auth/login

{
    "username": "admin",
    "password": "admin"
}
响应示例
{
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "userId": "usr_xxx",
    "username": "admin",
    "roles": ["admin"]
}
提示

默认用户名密码是 admin/admin（dev-up.sh 的 seed users）。把返回的 token 值复制下来，后续所有请求都需要它。

2 创建 Session（绑定 Agent）

POST http://localhost:8080/api/sessions

Authorization: Bearer <上一步拿到的token>
Content-Type: application/json

{
    "agent": "你的AgentA的id"
}
响应示例
{
    "id": "sess_1e76619274aa",
    "agentId": "agent_a",
    "status": "idle",
    "createdAt": 1789637470733,
    ...
}
不知道 Agent ID？

先调用 GET /api/agents（带 Bearer token）查看所有已注册的 Agent。

3 发送消息

POST http://localhost:8080/api/sessions/{sess_xxx}/events

Authorization: Bearer <token>
Content-Type: application/json

{
    "events": [
        {
            "type": "user.message",
            "payload": {
                "text": "你好"
            }
        }
    ]
}
4 获取 Agent 回复

等待 2-3 秒后：

GET http://localhost:8080/api/sessions/{sess_xxx}/events

Authorization: Bearer <token>
响应示例（事件列表）
[
    { "seq": 1, "type": "user.message", "payload": {"text": "你好"} },
    { "seq": 2, "type": "agent.message", "payload": {"text": "你好！有什么可以帮你的？"} },
    { "seq": 3, "type": "session.status_idle", "payload": {"status": "idle"} }
]

找 type: "agent.message" 的事件，其 payload.text 就是 Agent 的回复。

5 继续多轮对话

重复步骤 3、4，用同一个 sessionId 即可保持对话上下文。

流式对话（SSE）实时推送

SSE（Server-Sent Events）可以实时接收 Agent 的逐字回复，体验类似 ChatGPT 的流式输出。

方式一：curl（推荐，体验最好）

1 终端 1：开启 SSE 流监听
curl -N http://localhost:8080/api/sessions/sess_xxx/events/stream \
  -H "Authorization: Bearer <token>"

连接会保持打开，实时接收事件推送。

2 终端 2：发送消息
curl -X POST http://localhost:8080/api/sessions/sess_xxx/events \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"events":[{"type":"user.message","payload":{"text":"你好"}}]}'
3 终端 1 实时输出
event: user.message
data: {"seq":1,"type":"user.message","payload":{"text":"你好"}}

event: agent.message
data: {"seq":2,"type":"agent.message","payload":{"text":"你好！"}}

event: agent.message
data: {"seq":3,"type":"agent.message","payload":{"text":"有什么可以帮你的？"}}

event: session.status_idle
data: {"seq":4,"type":"session.status_idle","payload":{"status":"idle"}}

方式二：Postman SSE

1 Postman 窗口 A：开 SSE 流

新建请求：

GET http://localhost:8080/api/sessions/sess_xxx/events/stream
Authorization: Bearer <token>

点击 Send 后，在响应区域的下拉菜单中选择 Event Stream 格式（而非默认的 Pretty/Raw），即可实时看到 SSE 事件。

2 Postman 窗口 B（或 curl）：发消息

在另一个 Postman 标签页或终端中发送消息（同基础对话的步骤 3）。

3 在窗口 A 实时查看 Agent 回复

SSE 窗口会实时推送 agent.message 事件，逐字显示 Agent 的回复。

┌─ Postman 窗口 A / curl -N（SSE 流，保持连接）──────────────┐ │ GET /api/sessions/{id}/events/stream │ │ ← 实时推送: user.message, agent.message, session.status... │ └────────────────────────────────────────────────────────────┘ ┌─ Postman 窗口 B / curl（发消息）────────────────────────────┐ │ POST /api/sessions/{id}/events │ │ → {"events":[{"type":"user.message","payload":{"text":...}}]}│ └────────────────────────────────────────────────────────────┘
关键要点
  • 两个请求用同一个 sessionId
  • 每轮对话结束后 session status 变为 idle，可以继续发下一条消息
  • SSE 连接保持打开，可以持续接收多轮对话的事件

Postman 配置技巧

Collection 级别统一认证

在 Postman Collection 的 Edit → Authorization 中统一设置：

  1. Type 选 Bearer Token
  2. Token 填 {{jwt}}

这样所有请求自动带上认证头，不用每次手动填写。

自动提取 Token

在登录请求的 Tests 标签中添加脚本：

var json = pm.response.json();
pm.collectionVariables.set("jwt", json.token);

然后在其他请求的 Bearer Token 中填 {{jwt}}，登录一次后自动引用。

总结对比

方式 适合场景 优点 缺点
基础对话
(轮询 events)		 简单集成、快速验证 实现简单，Postman 友好 需要轮询等待，非实时
流式对话
(SSE stream)		 业务系统集成、实时交互 实时推送，体验好 需要 SSE 客户端支持
控制台 UI 开发调试、日常使用 开箱即用，完整功能 人工操作，无法程序集成
Webhook 外部事件触发（异步） 无需认证，fire-and-forget 拿不到回复，不适合对话
注意

Webhook 不适合对话场景。 如果你需要像调用 ChatGPT API 一样调用 Agent 并获取回复，请使用 Session API（基础对话或流式对话）。
