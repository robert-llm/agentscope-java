涉及的端点

端点 方法 说明 认证
/.well-known/oauth-protected-resource GET 受保护资源元数据（RFC 9728） 无需认证
/.well-known/oauth-authorization-server GET 授权服务器元数据（RFC 8414） 无需认证
/mcp/api/auth/authorize GET 请求用户授权（展示授权确认页） 无需认证
/mcp/api/auth/authorize POST 用户确认授权，生成授权码并重定向 无需认证
/mcp/api/auth/token POST 用授权码换取 Token / 刷新 Token 无需认证
/mcp/api/handbook/stream POST 员工手册流式对话（受保护资源） 需要 Bearer Token
/mcp/api/handbook/chat POST 员工手册同步问答（受保护资源） 需要 Bearer Token

详细步骤说明

  1. 首次调用受保护接口
    WorkBuddy 调用 POST /mcp/api/handbook/stream，未携带 Token。
    服务器返回 401 Unauthorized，响应头包含：
    WWW-Authenticate: Bearer resource_metadata="http://localhost:18099/.well-known/oauth-protected-resource"
  2. 获取受保护资源元数据
    WorkBuddy 根据 resource_metadata URL 请求 /.well-known/oauth-protected-resource。
    返回 authorization_servers 列表，告知授权服务器的地址。
  3. 获取授权服务器元数据
    WorkBuddy 请求 /.well-known/oauth-authorization-server。
    返回 authorization_endpoint、token_endpoint、scopes_supported 等端点信息。
  4. 引导用户授权
    WorkBuddy 在用户浏览器中打开授权页面：
    GET /mcp/api/auth/authorize?response_type=code&client_id=workbuddy_robert&redirect_uri=http://localhost:9002/route&scope=read&state=xxx
    用户看到授权确认页，点击「同意授权」。
  5. 接收授权码回调
    授权服务器 302 重定向至 redirect_uri，携带一次性授权码 code 和 state。
  6. 换取 Access Token
    WorkBuddy 后端用授权码调用 POST /mcp/api/auth/token，
    参数：grant_type=authorization_code、code、redirect_uri、client_id、client_secret。
    返回 access_token + refresh_token。
  7. 携带 Token 重新调用
    WorkBuddy 在请求头添加 Authorization: Bearer <access_token>，重新调用 /mcp/api/handbook/stream，正常获取数据。
  8. Token 过期后刷新
    access_token 过期后，使用 refresh_token 调用 POST /mcp/api/auth/token，
    参数：grant_type=refresh_token，获取新的 access_token（旧 refresh_token 轮换失效）。
