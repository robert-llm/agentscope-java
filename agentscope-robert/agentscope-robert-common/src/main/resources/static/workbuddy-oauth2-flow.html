端点一览表

端点 方法 说明 认证
/.well-known/oauth-protected-resource GET 受保护资源元数据（RFC 9728） 无需认证
/.well-known/oauth-authorization-server GET 授权服务器元数据（RFC 8414） 无需认证
/mcp/api/auth/admin/clients POST 动态客户端注册（DCR） 无需认证
/mcp/api/auth/authorize GET 请求用户授权（展示授权确认页） 无需认证
/mcp/api/auth/authorize POST 用户确认授权，生成授权码并重定向 无需认证
/mcp/api/auth/token POST 用授权码换取 Token / 刷新 Token 无需认证
/mcp POST MCP 协议端点（initialize / tools/list / tools/call） 需要 Bearer Token
/mcp DELETE 终止 MCP 会话 需要 Bearer Token
/mcp/api/handbook/stream POST 员工手册流式对话（REST 接口，备用） 需要 Bearer Token
/mcp/api/handbook/chat POST 员工手册同步问答（REST 接口，备用） 需要 Bearer Token

详细步骤说明

  1. OAuth2首次调用 MCP 端点
    WorkBuddy 向 POST /mcp 发送 JSON-RPC 消息 {"method":"initialize",...}，未携带 Token。
    服务器返回 401 Unauthorized，响应头包含：
    WWW-Authenticate: Bearer resource_metadata="http://localhost:18099/.well-known/oauth-protected-resource"
  2. OAuth2获取受保护资源元数据
    WorkBuddy 根据 resource_metadata URL 请求 /.well-known/oauth-protected-resource（RFC 9728）。
    返回 authorization_servers 列表，告知授权服务器的地址。
  3. OAuth2获取授权服务器元数据
    WorkBuddy 请求 /.well-known/oauth-authorization-server（RFC 8414）。
    返回 authorization_endpoint、token_endpoint、registration_endpoint、code_challenge_methods_supported 等。
  4. OAuth2动态客户端注册（DCR）
    WorkBuddy 调用 POST /mcp/api/auth/admin/clients 注册自身为合法客户端。
    服务器返回 client_id（如 wb_xxx）。WorkBuddy 是公共客户端，使用 PKCE，无需 client_secret。
  5. OAuth2引导用户授权（PKCE）
    WorkBuddy 在用户浏览器中打开授权页面，携带 code_challenge（S256）：
    GET /mcp/api/auth/authorize?response_type=code&client_id=wb_xxx&code_challenge=xxx&code_challenge_method=S256&redirect_uri=workbuddy://...&state=xxx
    用户看到授权确认页，点击「同意授权」。
  6. OAuth2接收授权码回调
    授权服务器 302 重定向至 redirect_uri（workbuddy://...），携带一次性授权码 code 和 state。
  7. OAuth2换取 Access Token（PKCE 验证）
    WorkBuddy 后端用授权码 + code_verifier 调用 POST /mcp/api/auth/token，
    参数：grant_type=authorization_code、code、redirect_uri、client_id、code_verifier。
    服务器验证 PKCE 后返回 access_token + refresh_token。
  8. MCPMCP 协议握手 — initialize
    WorkBuddy 携带 Authorization: Bearer <access_token> 向 POST /mcp 发送：
    {"jsonrpc":"2.0","method":"initialize","id":1,"params":{"protocolVersion":"2025-03-26","capabilities":{}}}
    服务器返回 protocolVersion、capabilities（支持 tools）、serverInfo（名称和版本）。
  9. MCPMCP 协议握手 — notifications/initialized
    WorkBuddy 发送确认通知 {"method":"notifications/initialized"}，握手完成。
  10. MCP发现可用工具 — tools/list
    WorkBuddy 发送 {"method":"tools/list","id":2}。
    服务器返回工具列表，包含 handbook_query 工具定义：
    { name: "handbook_query", description: "员工手册知识库问答", inputSchema: { message: string } }
  11. MCP调用工具 — tools/call
    WorkBuddy 发送 {"method":"tools/call","id":3,"params":{"name":"handbook_query","arguments":{"message":"年假政策"}}}。
    服务器通过 SSE 流式返回结果：
    event: message
    data: {"jsonrpc":"2.0","result":{"content":[{"type":"text","text":"根据公司规定..."}],"isError":false},"id":3}

MCP 协议格式参考

📡 传输协议：MCP Streamable HTTP（POST /mcp）

📋 消息格式：JSON-RPC 2.0

🔧 可用工具：handbook_query — 基于员工手册知识库的问答工具

📝 请求示例： 
POST /mcp HTTP/1.1
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
Mcp-Session-Id: session-xxx

{
  "jsonrpc": "2.0",
  "method": "tools/call",
  "id": 3,
  "params": {
    "name": "handbook_query",
    "arguments": {
      "message": "公司的年假政策是什么？"
    }
  }
}

event: session-established

event: message
data: {"jsonrpc":"2.0","result":{"content":[{"type":"text","text":"根据公司员工手册，年假政策如下：..."}],"isError":false},"id":3}
